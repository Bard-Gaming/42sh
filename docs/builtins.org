The builtins are grouped into 2 categories:
- [[Navigation]] - for navigating the file system
- [[Environment]] - for manipulating the shell's environment
- [[Local Variables]] - for manipulating local variables
- [[Aliases]] - for customizing commands
- [[Miscellaneous]] - for everything else


* Navigation
This section covers builtin commands that allow you
to navigate your OS's files and directories.

** cd
The ~cd~ command allows you to change to a given
directory. If no argument is given, this defaults
to the current user's home directory, as specified
in the environment.

*** Arguments
- ~path~? : path to change directory to (relative or absolute)

*** Notes
The ~path~ argument also has special values, which allow for easier
manoeuvring. These values are:
- <no args>: Go to home directory
- ~-~: Go to previous directory

*** Example
#+begin_src bash
cd  # changes directory to $HOME
cd dir1/dir2  # changes to dir2 which is in dir1 relative to current work directory

cd nonexistant_dir  # error
cd dir1 dir1/dir2  # error (too many args)
#+end_src

** exit
The ~exit~ command allows you to exit the current shell
process with a given exit status.

*** Arguments
- ~exit status~? : exit status to exit the process with

*** Notes
If no exit status is specified, the last exit status is
used instead.

The exit status is only a single byte, so the value can't
be negative or over 255.

*** Example
#+begin_src bash
exit 42  # exit the shell with the exit status 42

exit a  # error
exit  # exits with status 84 (the command 'exit a' resulted in an exit status of 84)
#+end_src


* Environment
This section covers builtins that manipulate the shell's
environment.

** env
The ~env~ command allows you to display the current
environment. It does not take any arguments.

*** Example
#+begin_src bash
env  # displays the environment

env a  # error
#+end_src

** setenv
The ~setenv~ command allows you to add or overwrite values
that are stored in the environment. If no arguments are given,
the current environment is displayed instead (same as the [[*env][env]] command).

*** Arguments
- ~name~? : name of the value that should be added to the environment
- ~value~? : value to be associated with the name in the environment (default: ~""~)

*** Example
#+begin_src bash
setenv  # displays environment (same as calling env)

setenv a  # sets the env variable "a" to value ""
setenv a 3  # sets the env variable "a" to value "3"

setenv a b c  # error
#+end_src

** unsetenv
The ~unsetenv~ command allows you to remove one or more
values from the environment.

*** Arguments
- ~name~\+: name of the value to be removed

*** Example
#+begin_src bash
setenv a "hello"  # creates envvar
env  # displays a=hello
unsetenv a  # removes envvar
env  # doesn't display a

setenv a "test1"
setenv b "test2"
env
unsetenv a b  # removes both a and b

unsetenv  # error
#+end_src


* Local Variables
The section covers the shell's builtins which allow
to manipulate local variables. Local variables differ
from environment variables in that they don't get passed
onto whichever programs are run.

** set
The ~set~ builtin allows you to update a shell's local
variable with a given value (or an empty string if none
is given).

*** Arguments
- ~name-value~\+: pair of name to be associated with value

*** Example
#+begin_src bash
set a=3
set b = "hi!"
set c = 4 d = "`ls`"

echo "$a $b $c $d"
#+end_src


** unset
The ~unset~ builtin allows you to /unset/ a local variable,
as the name implies. Unsetting a variable is not the same as
using ~set~ to set its value to nothing, as the variable will
then remain /defined/.

*** Arguments
- ~names~\ast: variable names to unset

*** Example
#+begin_src bash
set a = "hello!"

echo $a  # prints "hello!"
unset a
echo $a  # prints ""
#+end_src


* Aliases
This section covers all builtins related to command
aliasing.

** alias
The ~alias~ builtin allows you to replace a command
with one or more other commands.

*** Arguments
- ~command~: command to replace
- ~new command(s)~: new commands to replace the old one with

*** Example
#+begin_src bash
alias ls "ls --color=auto"

ls  # runs ls --color=auto

alias glog "git log"

glog --help  # runs git log --help

alias slow_git "echo loading git... && sleep 5; git"

slow_git log  # runs "git log" after printing the message and waiting 5 seconds

alias  # prints all aliases
alias slow_git  # prints the alias associated to slow_git
#+end_src

* Miscellaneous
This section covers all other builtins that can't
quite be classified into their own sections.

** exec
The ~exec~ builtin allows you to replace the shell's
image with another process.

*** Arguments
- ~command~: command to be run
- ~arguments~\ast: arguments to be passed to the command

*** Example
#+begin_src bash
exec ls -t  # effectively starts ls and exits the shell

exec 42sh  # similar to how reload works
#+end_src

** reload
The ~reload~ builtin allows you to reload the shell,
allowing for on-the-fly code manipulation.

*** Notes
The ~reload~ builtin is advantageous in that it doesn't
kill and recreate a new process, making it faster.
Additionally, using the ~reload~ builtin allows you to
preserve the shell's environment when reloading.

Furthermore, it should be noted that reloading inside of
a pipeline results in an error, as the behaviour resulting
from a shell reload within a pipe would be weird and messy.

*** Example
#+begin_src bash
reload  # reloads the shell

reload arg  # error
echo test | reload  # error
#+end_src
